# Project 3: Third-party vendor assessment

[← Repository home](../../README.md)

## Objective

Build a vendor security questionnaire with five sections and a scoring system, complete it for a public service using its published security documents, and produce a scorecard and a one-page report.

## Deliverables

| File | What it contains |
|---|---|
| [Vendor questionnaire template](vendor-questionnaire-template.md) | 25 questions in five sections (Governance, Access Control, Data Protection, Incident Response, Compliance), scoring rules, a criticality scorecard and a risk matrix |
| [Completed assessment: Notion](vendor-assessment-notion.md) | All 25 answers scored, with evidence summaries and sources |
| [Vendor risk scorecard](vendor-risk-scorecard.md) | Criticality ranking of all 12 vendors, the risk matrix, Notion's result and the assessment queue |
| [Vendor assessment report](vendor-assessment-report.md) | One-page report with strengths, gaps and conditions of approval |

## Key results

- Notion scores **40 of 50 (80%)**, an Acceptable band; overall vendor risk **Medium**, approved with five conditions.
- 12 vendors ranked by criticality: 3 Critical, 4 High, 3 Medium, 2 Low. Only Notion is assessed so far.

## Improvements over the basic brief

- Added a **criticality tier** before the questionnaire, so the depth of review matches the risk, and a **risk matrix** that combines criticality with the security score.
- Scored each answer **for the plan actually used**, so features locked to Enterprise plans are marked Partial rather than Yes.
- Recorded **where each answer came from** and what could not be confirmed, so the assessment can be checked and repeated.
- Turned the result into **conditions with owners and dates**, and linked it to the control matrix (A.5.19).

## Honest limits

The assessment is a desk review of public pages read on 19 November 2026. No vendor was contacted and no audit report was reviewed. It is practice for the method, not a verdict on Notion.
